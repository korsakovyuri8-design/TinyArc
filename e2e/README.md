# Сквозные сценарии

Проверяют то, чего не видит модульный тест: cookie, перенаправления, серверные
действия и то, что показано на экране.

```bash
npm run db:seed          # свежий стенд
npm run build && npm start &
npm run e2e
```

Сценарии ходят по собранному приложению, а не по dev-серверу: в бою работает
именно сборка, и именно её поведение имеет смысл проверять.

Порядок в цепочке имеет значение в одном месте: `privacy.mts` идёт последним.
Он единственный необратимо меняет стенд — обезличенный специалист перестаёт
быть собой, — и всё, что после него ищет людей по адресам, начнёт находить
пустоту. Остальные сценарии друг от друга не зависят.

Ограничитель частоты живёт в памяти процесса, поэтому второй прогон подряд по
тому же серверу упирается в пределы: напоминание ключа берёт из дорогого
счётчика два обращения из трёх. Между прогонами сервер поднимается заново —
это и есть «свежий стенд».
